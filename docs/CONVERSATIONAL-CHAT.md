# Simple conversational practice

The main screen has one question box, three support choices and Attach work. Optional question starters and an explanation preference sit in the welcome area. More options holds secondary tools; teacher/class/project views are unchanged.

A bounded local rule recognises short requests such as “I’m stuck” or “I don’t understand equations”. It asks one clarification question, with Not sure—start with me to skip. Concrete questions containing numbers/equations and ordinary concept questions go straight to practice. The original question and optional clarification are sent together to AI, within the existing 2,000-character limit. Editable starter chips choose a topic and fill a draft without sending it. This is prompting support, not a diagnostic inference or a new autonomous agent.

Personalisation uses the learner-selected grade/curriculum/topic, Short steps / Standard / More detail, and their stated difficulty. The chosen style is retained in this mounted practice view, including New chat, and clears on refresh/sign-out/context change. It is not stored as an ability profile. AI instructions ask for one short conversational challenge, short explanations and age/subject safeguards. Original starter activities remain fixed authored content; reading preference does not rewrite those activities.

The backend attempt → explain → compare → apply → independent → reflect states and gates are retained. A first attempt or “I’m stuck” is required before hints. Independent practice hides earlier writing, direct explanations, examples, visual models, attachments and paper links. Formative browser practice is not a supervised assessment. Earlier thinking and final answer comparisons are collapsed. Returning from direct explanations to guided practice marks prior worked support. Chat prose is not sent for automatic judgement; the model comparison is labelled as such. Attach work has its separate explicit permission/confirmation process for AI feedback.

Attachments now ask for Photo, PDF or Type instead. Only the chosen input is visible; transcription/question fields appear after text is read or typing is selected. Permission is still visible before transmission. Longer privacy details are available on demand, with provider retention and clear/close behaviour unchanged. PDF state is retained when switching methods; Clear destroys it. Main-composer stickiness is disabled while a secondary panel is open so it does not cover the attachment controls. Optional microphone privacy controls remain explicit and collapsed by default.

Validation: six frontend suites including clarification bounds and stage guidance; build/type check/lint; 37 backend tests including the authored question appearing with a blank-question direct explanation. Browser checks cover optional starter editing, preference selection, clarification with real AI, attempt-gated hints, explanation/application/independent flow, direct → guided, PDF sample preview/transcription into newly revealed fields, permission/confirmation gating, secondary visuals and narrow layout. Real handwriting accuracy and marking validity have not been established. Further usability testing with learners/teachers is needed; simpler layout alone does not prove ease of use or learning.
